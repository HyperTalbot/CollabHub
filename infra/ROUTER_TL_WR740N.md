# Настройка роутера TP-Link TL-WR740N для звонков (WebRTC)

## Что этот роутер решит, а что — нет

| Сценарий | Решается роутером? |
|---|---|
| Ноут ↔ телефон в одной домашней сети (тишина при «соединено») | **Да** — включить NAT Loopback / ALG |
| Звонки извне через интернет (мобильный CGNAT, другой провайдер) | **Нет** — нужен TURN на сервере с белым IP (см. docker-compose.yml) |

⚠️ Важно: у билайна адрес `195.178.4.137` — это общий (серый) адрес NAT провайдера.
Проброс портов на этом роутере НЕ сделает ваш компьютер доступным из интернета:
пакеты приходят на адрес провайдера, а не к вам. Поэтому для внешних звонков
единственный путь — свой coturn на VPS/сервере с белым IP.

## Шаг 1. Обновите прошивку

Интерфейсы TL-WR740N бывают разные (старый синий «Archer-подобный» и классический).
Если пункта из шагов ниже нет — вероятно, старая прошивка: обновите с оф. сайта
tp-link.com (раздел Support → ваша модель → Firmware, берите версию под ваш hardware v1/v2/v3/v4,
указан на наклейке снизу роутера). После обновления — сброс настроек может потребоваться повторно.

## Шаг 2. Включите NAT Loopback (главное для тишины в одной сети)

Классический интерфейс:
`Transmission → NAT Forwarding → NAT Loopback` (или «ALG») → включить (Enable), сохранить.

Новый интерфейс Archer:
`Дополнительно → NAT → NAT Loopback` → Enable.

Что это даёт: когда оба устройства в LAN пытаются соединиться через свои внешние
(STUN/srflx) адреса `195.178.4.137:порт`, роутер начнёт разворачивать такие пакеты
обратно внутрь сети (hairpin NAT). Без этого медиа уходит «на сторону провайдера»
и возвращается в пустоту — ровно ваш симптом «дозвонился, но полная тишина».

## Шаг 3. SIP ALG — отключить

`Transmission → NAT Forwarding → ALG` (или `Дополнительно → NAT → ALG`) →
снимите галку с SIP ALG (и желательно с PPTP/L2TP, если есть) → сохранить.
SIP ALG портит RTP/ICE-пакеты. Если отдельного переключателя SIP нет — пропускаем шаг.

## Шаг 4. Перезагрузка роутера

`System Tools → Reboot`. Затем перезагрузите ноут и телефон (чтобы заново получить
IP по DHCP и пересобрать ICE-кандидаты).

## Шаг 5. Проверка

1. Позвоните ноут ↔ телефон в одной Wi-Fi сети.
2. Во время звонка посмотрите плашку «маршрут медиа: …» в CallModal:
   - было `srflx→srflx` и тишина → после NAT Loopback должно заработать;
   - стало `host→host` и звук есть → готово;
   - всё ещё тишина → пришлите строку «маршрут медиа» и значения in/out audio bytes.

## Шаг 6. Для звонков через интернет (не через роутер)

Поднять coturn на сервере с белым IP (файл infra/docker-compose.yml уже готов):

```bash
# на сервере с белым IP:
docker compose -f infra/docker-compose.yml up -d
# TURN_EXTERNAL_IP=<белый IP сервера> в env или в самом файле
```

Открыть на сервере firewall: TCP+UDP 3478 и UDP 49152–49200.
Затем во фронте в .env.local:

```
NEXT_PUBLIC_TURN_URL=turn:<БЕЛЫЙ_IP>:3478
NEXT_PUBLIC_TURN_USERNAME=collabhub
NEXT_PUBLIC_TURN_CREDENTIAL=<пароль из docker-compose, смените SuperSecretChangeMe2024>
```

Пересобрать фронт. Признак успеха в диагностике: появятся relay-кандидаты,
плашка «TURN-сервер недоступен» исчезнет.
